# Mockwave v0.3.0 Design

**Date:** 2026-05-26
**Status:** Approved

## Goal

Two improvements before the v0.3.0 release:

1. **CLI docs** — enrich `mockwave mcp --help` with a tool list and example workflows
2. **`generate_from_openapi` MCP tool** — given an OpenAPI 2.0 or 3.0 spec (URL or file), auto-generate Mockwave rules and simulations for every endpoint

---

## 1. CLI Docs: `mockwave mcp --help`

### What changes

`cmd/mockwave/mcp.go` — update the Cobra command's `Long` description and add an `Example` field.

**`Long` additions:**
- List all 15 available MCP tools grouped by category (Rules, Simulations, Observability)

**`Example` field (new):**
```
  # Local instance (default port)
  mockwave mcp --admin-url http://localhost:9090

  # Remote sandbox
  mockwave mcp --admin-url https://mockwave.sandbox.example.com

  # Custom local port
  mockwave mcp --admin-url http://localhost:3001
```

### No new files

Single change to `cmd/mockwave/mcp.go`.

## 2. `generate_from_openapi` MCP Tool

### Architecture

```
Claude calls generate_from_openapi(source, overwrite, path_prefix, tags)
    │
    ▼
internal/mcp/openapi.go
    ├── fetch spec: URL → http.GET  |  file path → os.ReadFile
    ├── detect version: "swagger":"2.0" → kin-openapi/openapi2 converter
    │                   "openapi":"3.x" → kin-openapi/openapi3 loader
    ├── filter paths by path_prefix and/or tags
    ├── generate []GeneratedPair{Rule, Simulation}
    │
    ▼
internal/mcp/tools.go — handleGenerateFromOpenAPI
    ├── conflict check: Client.GetRule + Client.GetSimulation per ID
    ├── conflicts + overwrite=false → return isError with conflict list
    └── create: Client.CreateSimulation × N, Client.CreateRule × N
               → return summary text
```

### Tool parameters

| Param | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `source` | string | ✅ | — | URL (`https://...`) or file path (`/path/to/spec.yaml`) |
| `overwrite` | bool | — | `false` | Replace existing rules/sims with same IDs |
| `path_prefix` | string | — | — | Only generate for paths starting with this prefix |
| `tags` | string | — | — | Comma-separated OpenAPI tags to include (e.g. `"Orders,Users"`) |

### ID generation

Path parameters `{x}` are normalised to the literal `id`:

```
GET  /users/{id}/orders  →  get-users-id-orders
POST /orders             →  post-orders
DELETE /items/{id}       →  delete-items-id
```

Simulation ID = rule ID + `-sim` (e.g. `get-users-id-orders-sim`).

### Per-endpoint generation

**Simulation:**
- `protocol`: `"http"`
- `response.status`: first 2xx status code defined in the spec; fallback `200`
- `response.body`: example value from spec if present; otherwise schema-derived minimal object — required fields filled with typed zero values (`""`, `0`, `false`, `[]`, `{}`)
- Paths with no 2xx response defined are skipped and reported in the summary

**Rule:**
- `match.method`: HTTP method (uppercase)
- `match.path`: OpenAPI path with `{param}` replaced by glob `*` (e.g. `/users/{id}` → `/users/*`)
- `buckets`: single bucket `{weight: 100, action: "simulate", simulation_id: "<id>-sim"}`

### Conflict handling

When `overwrite=false` (default) and one or more IDs already exist:

```
3 conflicts found — re-run with overwrite:true to replace:
  - rule: get-users
  - rule: post-orders
  - simulation: get-users-sim
```

When `overwrite=true`: existing rules/sims are replaced via `PUT`, new ones created via `POST`.

### Success response

```
Generated from https://petstore.example.com/openapi.json:
  15 rules created
  15 simulations created
  2 paths skipped (no 2xx response defined)
```

### Error cases

| Situation | Result |
|-----------|--------|
| URL fetch fails | `isError:true` — "failed to fetch spec: HTTP 404" |
| File not found | `isError:true` — "failed to read spec: ..." |
| Invalid YAML/JSON | `isError:true` — "invalid spec: ..." |
| Unsupported version | `isError:true` — "unsupported spec version (must be OpenAPI 2.0 or 3.0)" |
| No paths after filter | `isError:true` — "no paths matched path_prefix=/xyz or tags=[Foo]" |
| Conflicts + overwrite=false | `isError:true` — conflict list |
| Admin API error mid-create | `isError:true` — "created 3/15 rules before error: HTTP 503 ..." |

## File Structure

| Action | Path | Responsibility |
|--------|------|----------------|
| Modify | `cmd/mockwave/mcp.go` | Add tool list + examples to `--help` |
| Create | `internal/mcp/openapi.go` | Spec fetch, parse, filter, Rule+Simulation generation |
| Create | `internal/mcp/openapi_test.go` | Unit tests using embedded fixture specs |
| Create | `internal/mcp/testdata/petstore3.yaml` | Minimal OpenAPI 3.0 fixture |
| Create | `internal/mcp/testdata/petstore2.yaml` | Minimal Swagger 2.0 fixture |
| Modify | `internal/mcp/tools.go` | Add `handleGenerateFromOpenAPI` |
| Modify | `internal/mcp/server.go` | Register `generate_from_openapi` tool |
| Modify | `go.mod` / `go.sum` | Add `github.com/getkin/kin-openapi` |

## Dependencies

- `github.com/getkin/kin-openapi` — OpenAPI 2.0 + 3.0 parsing, `$ref` resolution, schema traversal, example extraction. Used for both loading remote URLs and local files.

---

## Testing

**`openapi_test.go`** — pure unit tests, no network, no admin API:
- `TestGeneratePairs_OpenAPI3` — parse `petstore3.yaml`, assert correct Rule+Simulation pairs
- `TestGeneratePairs_Swagger2` — parse `petstore2.yaml`, assert same output as 3.0
- `TestGeneratePairs_PathPrefixFilter` — only `/pets` paths included
- `TestGeneratePairs_TagsFilter` — only `"Pets"` tagged paths included
- `TestGeneratePairs_SchemaBody` — no example in spec → typed zero values
- `TestGeneratePairs_ExamplePreferred` — example present → used over schema
- `TestGeneratePairs_SkipsNoSuccessResponse` — path with no 2xx → skipped
- `TestFetchSpec_URL` — httptest.Server serving fixture YAML → parsed correctly
- `TestFetchSpec_File` — local file path → parsed correctly
- `TestFetchSpec_InvalidYAML` — error returned

**`tools_test.go`** additions:
- `TestGenerateFromOpenAPI_Success` — full flow via ServerTool.Handler + fake admin server
- `TestGenerateFromOpenAPI_Conflict` — conflict returned when IDs exist + overwrite=false
- `TestGenerateFromOpenAPI_Overwrite` — overwrite=true replaces existing

---

## Out of Scope

- gRPC / SOAP / GraphQL spec import (OpenAPI is HTTP REST only)
- Response body generation for `allOf`/`anyOf`/`oneOf` composition (generates `{}` fallback)
- Authentication headers for fetching private spec URLs (future work)
- Dry-run / preview mode (future work)
